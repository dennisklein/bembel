Architecture and stack

bembel is one Go binary with an embedded web UI, and one PostgreSQL 18 database. Agents on the DNS, DHCP and InfiniBand servers pull signed export bundles. Integrations use the same public API as the web UI. This chapter describes the parts and gives the reasons for each technology choice.

  • The OpenAPI 3.1 document api/openapi.yaml is the contract. The server stubs and all clients are generated from it. Today it is a sketch that grows with each chapter (REST API).
  • Go, not Rust: one language for the server, the CLI, the Kubernetes controllers, the Cluster API provider and the external-dns webhook. PostgreSQL does the heavy IP work, so the speed of Rust buys little.
  • PostgreSQL 18 enforces the model: inet and cidr, GiST exclusion against overlaps, ltree, uuidv7(), pgvector.
  • SvelteKit with Svelte 5, built to static files and embedded in the binary. No Node.js at run time.
  • The server is stateless. Three or more replicas run behind one service. Workers coordinate through PostgreSQL locks and lease rows.
  • mise pins all tools. mise run is the only entry point for builds, tests and docs.

API first

The OpenAPI document is written by hand and reviewed like code. Generators make the rest:

Why spec first and not code first

The API is the product for the integrations. A code-first framework (huma) makes the spec a side effect of Go types, and a refactor can change the contract without a review. With the spec first, each change to the contract is a diff in api/openapi.yaml. ogen makes typed handlers, so the server cannot return a shape that the spec does not allow. If ogen does not support a needed OpenAPI 3.1 feature, oapi-codegen with the strict server is the fallback.

Database: PostgreSQL 18

PostgreSQL is the only store. It enforces the rules of the model (model.html#schema), so a bug in the server cannot make overlapping prefixes or duplicate addresses.

FeatureUse in bembel
inet, cidr, operators <<, >>=, &&Containment, overlap, the prefix tree, reverse zones.

ltreeDNS names (labels reversed) and location paths for subtree scopes.

LISTEN / NOTIFYA wake-up signal for the outbox stamper and delivery, and for the binding cache. Each pod holds one direct connection for LISTEN, outside the PgBouncer pool. The outbox table holds the data.

pgvectorEmbeddings for the hybrid search and the assistant (assistant.html#embeddings).

PostgreSQL 19

PostgreSQL 19 is a release candidate (GA planned for 2026-11-19). bembel targets 18 and tests 19 in CI as soon as it is out. bembel uses no extension that managed PostgreSQL services do not offer, except pgvector, which most of them offer.

Frontend: SvelteKit

The web UI is SvelteKit 3 with Svelte 5 runes, TypeScript and adapter-static. The build output goes into the Go binary with go:embed. The server serves the files and the API on one origin, so the browser needs no CORS, and the session cookie is SameSite=Lax, with the X-Bembel-Csrf header and an Origin check on write calls (see Access control).

  • API calls: openapi-fetch with types from openapi-typescript.
  • Tables: TanStack Table (sort, filter, virtual rows for 40 000 hosts).
  • Live updates: the event stream (/v1/events/stream, server-sent events) refreshes open lists.
  • Help texts: the same embedded files as bembel help (assistant.html#help).
  • Tests: Vitest for logic, Playwright for end-to-end flows and screenshots.

Why not server-rendered HTML with htmx

repoctl and brig render HTML on the server. bembel has dense, editable tables, a rack view, a prefix tree with drag selection and an assistant panel with streaming. These parts need client-side state. A static SvelteKit build keeps the deployment simple (no Node.js on the server) and uses only the public API, which proves that the API is complete.

Toolchain: mise

mise.toml pins every tool. With the first code commit, mise.lock also pins the checksums. A new contributor runs mise install and has the same versions as CI. Today the repository holds only the design record, so mise.toml pins only Python and Node and has the docs tasks. The first code commit extends it as follows. Tools that mise fetches from GitHub releases get the http: backend with a checksum per platform, as in brig.

Deployment

bembel runs in Kubernetes with a Helm chart, or on a VM with the .deb or .rpm package and a systemd unit. The chapter Operations gives the details.
