Core model

This chapter defines the objects of bembel and their relations. All other chapters, the API, the CLI and the web UI use these words with one meaning. Read it before the mapping chapters.

  • bembel is the source of truth for addresses, names and networks. The database enforces the rules: a prefix is unique in its VRF, an address is unique in its VRF, sibling prefixes do not overlap.
  • Prefixes make one tree per VRF. bembel computes the tree from containment. Nobody edits a parent link by hand.
  • bembel derives what it can: A, AAAA and PTR records come from addresses, reverse zones come from subnets, DHCP reservations come from interfaces. A derived value is never stored twice.
  • Each object has an owner team, a source and, for an integration, a managed_by value. Thus each object has one writer.
  • IPv4 and IPv6 are equal. A dual stack network is a pair of subnets on one VLAN or IB partition.
  • Each change is a row in a history table, an audit event and an event for webhooks. The API is the only way to change data.

Principles

The model follows six rules. Each rule removes a problem of OpenNetAdmin or of other IPAM tools (decision.html#problems).

RuleWhat it meansProblem that it removes
Constraints in the databasePostgreSQL checks uniqueness, overlap and references. The application checks only what SQL cannot express.ONA has no foreign keys. NetBox checks uniqueness only in clean(). Both allow inconsistent data after a bug or a direct write.
One tree per VRFThe parent of a prefix is the smallest prefix that contains it in the same VRF. A trigger keeps parent_id correct.ONA has no prefix hierarchy. Its blocks are free ranges without relation to subnets.
Derive, do not copyA record, a reverse zone or a reservation that follows from other data is computed. Its source is the only place to change it.ONA keeps A and PTR rows that can point to deleted interfaces.
One writer per objectAn object has a source. An integration that manages an object is its only writer.A sync and a user overwrite each other.
Typed links, no generic linksEach relation is a foreign key to one table. bembel uses no "any object" link.NetBox uses generic foreign keys for assignments and scopes. The database cannot check them.
The API is the modelEach object kind is one REST resource with the same fields. The UI and the CLI use only the API.ONA mixes UI forms, dcm.pl modules and direct SQL.

A tag has one text form, key=value. It is used in query filters, in scope terms, in map files and in the NetBox Tag.name. The rules are:

  • The key matches [a-z0-9._-]+.
  • The text splits at the first =. The value is any string, and it can contain more = characters.
  • A bare key without = matches any value of that key in a filter or a scope term.

Examples: the filter ?tag=role=login (also sent as ?tag=role%3Dlogin), the scope terms tag=os_cloud=os-prod and tag=feed=fw-pan-01.

A team is an owner of objects. It maps to a group of the IdP, for example hpc-ops to the top-level Keycloak group hpc-ops. bembel sees that group as kc:hpc-ops. A team is not a tenant with an own data space: all teams see the same tree, and bindings control who can change what (access.html#scopes).

A custom attribute is a typed field that an admin declares for one kind: string, integer, boolean, date, enum, url, json. The declaration has a key, a label, a JSON Schema and an optional default. ONA custom attributes import to custom attributes with the same key (map-ona.html#attributes).

Addressing

Addressing has four core kinds: VRF, prefix, range and address. A claim is an address in status claimed. VLANs and fabrics give the L2 context of a subnet (fabrics).

VRF

A VRF is an independent address space. The same prefix can be in two VRFs. In one VRF, a prefix and an address are unique. The default VRF is global. The story has four VRFs: global (campus), hpc-fabric (cluster internal InfiniBand and RoCEv2), oob (BMC and management) and os-provider (OpenStack provider networks). A VRF has an optional route distinguisher and route targets (routing).

Why a VRF in a campus without MPLS

ONA has one global space and rejects overlaps. The organisation already reuses addresses: the InfiniBand fabric, the BMC network and the OpenStack provider networks are separate routing domains. With a VRF, bembel models them as they are and still rejects overlaps inside each one.

Prefix

A prefix is a CIDR block in a VRF, IPv4 or IPv6. A prefix is one of two kinds:

  • A container holds only other prefixes, for example an aggregate from a RIR, the block of a site or the block of a team. A container can be a prefix pool: callers can allocate child prefixes from it (allocation.html#prefix-allocate).
  • A subnet is an L3 network. It holds ranges and addresses. It has a gateway, a fabric, a VLAN or an IB partition, a site, a DHCP scope and DNS defaults.

The twin link of a dual stack network has these rules:

  • The link is symmetric. When A has twin_id B, then B has twin_id A.
  • The twin is a subnet of the other family. A subnet has at most one twin (UNIQUE (twin_id)).
  • Both subnets share the VLAN or IB partition, the fabric and the site.
  • A deferred constraint trigger checks these rules at commit. A VLAN or partition change on one side changes the other side in the same transaction, after a confirm in the UI.

Range

A range is a contiguous span of addresses in one subnet. It does not need CIDR alignment. Its purpose tells bembel how to treat the addresses in it. The field is always purpose, with one of five values. An allocate request without a range skips every range except static. A request that names a range allocates only inside that range.

Utilisation counts as used each address row and each address in a range with the purpose dhcp-pool, reserved, infrastructure or lb-pool, each address once (allocation.html#utilisation). A load balancer pool is a range in the subnet, not a child prefix, because a subnet has no child prefix.

Address

An address is one IP address in a subnet. It has a status, a DNS name (fqdn) and an optional interface. The export rules below apply to DNS records and to DHCP reservations in the same way.

StatusMeaningDNS and DHCP
allocatedIn use. Normally on an interface.Derived records and a reservation (if a MAC is known).
reservedKept for a purpose, not in use yet.Records only if a name is set.
claimedHeld with an expiry (expires_at). See claim.No records and no reservation, unless the claim has publish: true.
deprecatedReleased, in a grace time (deprecated_until) before it is free. Default 7 days (allocation.default_release_grace).No records (unless dns.publish_deprecated). Blocked until deprecated_until.

An address with shared: true is on several interfaces: a VIP, an anycast address or a VRRP address. A trigger allows more than one address_interface row only for a shared address. A shared: false address has at most one. ONA interface clusters import to shared addresses. An address in an IPv6 subnet can be observed: a SLAAC or EUI-64 address that a sync, an agent or a lease report found. bembel stores observed, last_seen_at and last_seen_source, and shows the address, but does not allocate it. A release of an observed address that its source still reports gives 409 address.observed.

Claim

A claim is a temporary hold on an address with an expiry. It is not a separate object: it is an address row with the status claimed and an expires_at. The caller makes it with POST /v1/prefixes/{id}/addresses:allocate and a claim_ttl, for example PT10M. The caller confirms it with POST /v1/addresses/{id}:confirm when the resource exists, and the address becomes allocated. Otherwise the reaper deletes the row after the expiry. Only addresses are claimed. A prefix is never claimed.

The Neutron IPAM driver and the libvirt hook (bembel vm prepare) use claims, because their transactions can fail after the allocation (allocation.html#claims). The Cluster API provider does not use claims. It allocates directly, one address for each IPAddressClaim, and finds the address again by its external_ref.

VLAN and VLAN domain

A VLAN has a VID from 1 to 4094 and a name. A VLAN domain is the scope in which a VID is unique: a campus, a hall or one fabric. ONA VLAN campuses import to VLAN domains. A subnet refers to one VLAN. Two subnets of a dual stack network refer to the same VLAN.

Fabrics

A fabric is the L2 technology domain of a subnet. It answers the question "what carries this network": Ethernet, Ethernet with RoCEv2, or InfiniBand. The chapter Fabrics gives all details.

An IB partition has a P_Key from 0x0001 to 0x7ffe (0x7fff is the Default partition), a name, an IPoIB flag, an MTU and a membership (full or limited) per member. bembel stores the 15-bit base key, unique in the fabric. The membership is per member, not part of the key. An input with the top bit (the full member bit) set is changed to the base key, so both forms name the same partition. The 16-bit form appears only as a value per member, and in Linux child interface names such as ib0.8001. In the story, kestrel-ipoib is 0x0001. A QoS profile holds the lossless settings of a RoCEv2 fabric. Host and switch configuration tools read it from the API.

Hosts and interfaces

A host is a named logical system with interfaces. Its kind (host_kind) is physical, vm, hypervisor, appliance or container-node. A host has a primary FQDN, an owner team, tags and an optional asset link to a device of the asset mirror. An interface is a network port of a host. It has a name, a fabric and an identifier: a MAC for Ethernet, a port GUID (port_guid, 16 lowercase hex digits, for example 0c42a1030071a2b4) and the 20-byte IPoIB hardware address for InfiniBand. An interface holds zero or more addresses.

An ONA interface is an address

In ONA, one interface row has one IP address and an optional MAC. A host with an IPv4 and an IPv6 address on one NIC has two interface rows. The import merges rows with the same host and MAC (or the same name) into one bembel interface with several addresses (map-ona.html#interfaces).

Virtual machines

A VM is a host with host_kind vm. It has a runs_on link to a host with host_kind hypervisor and a platform: libvirt, openstack or other. All VMs use this one model. Only the source differs: the bembel-agent on a Debian libvirt hypervisor reports libvirt VMs, and the OpenStack sync reports OpenStack VMs. A live migration changes only runs_on. The chapter Virtual machines gives the agent, the libvirt hook and the cloud-init data.

DNS

A zone is a forward or reverse DNS zone. It is in one or more DNS views, it has SOA and NS settings, an owner and DNS servers as delivery targets. A DNS view is a split-horizon view, for example internal and external. A record is a resource record with name, type, TTL and data in a view.

bembel has two classes of records:

  • A derived record comes from an address with a DNS name: the A or AAAA record in the forward zone and the PTR record in the reverse zone. A user changes it only through the address. When an address moves to another IP, both records move.
  • A manual record is edited directly: CNAME, MX, SRV, TXT, NS, CAA, and A or AAAA records for names outside bembel. A CNAME can point to any name, also outside bembel.

Reverse zones are computed from the subnets: 20.10.in-addr.arpa for 10.20.0.0/16, nibble zones for IPv6, and RFC 2317 zones with the parent CNAMEs for small IPv4 subnets. The BIND export writes all zones per DNS server and per view (dns.html#export).

DHCP

A DHCP scope holds the DHCP settings of one subnet: on or off, DHCP servers, options and a failover pair. A DHCP pool is a range with the purpose dhcp-pool. A reservation is not a separate object that a user edits: it follows from an address on an interface with a MAC, or with a client identifier for IPoIB. The address status decides if the export writes it (address). A DHCP option has a code and a value at the global, server, scope or host level. A failover pair is two DHCP servers that share the pools of a scope. The ISC dhcpd export writes dhcpd.conf per server (dhcp.html#export).

A DHCP scope has the read-only vrf of its subnet. ISC dhcpd 4.4 has one flat address space and no VSS (RFC 6607). Thus one DHCP server, and both peers of a failover pair, must not serve overlapping subnets from different VRFs. bembel refuses such a scope at write time with 409 dhcp-scope.vrf-overlap, which names both scopes and both VRFs. The export checks the same rule again. Lease ingestion finds the address through the server: (server, IP) gives the scope, the scope gives the subnet and its VRF, and the VRF gives the address (dhcp.html#scopes).

Assets

The asset mirror is a read-only copy of FNT Command: site, building, floor, room, row, rack, device and port. Each object has source=fnt, external_ref (the ELID) and synced_at. bembel adds only links: an asset link from a host to a device, and from an interface to a port. A sync matches them by serial, asset tag, MAC and hostname, in this order (assets.html#matching).

Routing

bembel is the source of truth for routing values, not for router configuration. An ASN is an autonomous system number with an owner, from an ASN range. A VRF has a route distinguisher and import and export route targets. A static route has a VRF, a destination prefix, a next-hop address and an owner. A prefix with announce: true goes into the prefix lists that bembel exports for FRR, BIRD, Junos and Arista EOS (routing.html).

Firewall groups

An address group is a named dynamic set of addresses and prefixes. A filter defines it, for example "hosts with tag role=login in VRF global". bembel computes the members after each change and publishes the group as a feed: an nftables set, a firewalld ipset, a plain text list for external dynamic lists, or JSON. Firewall policies stay in the firewall tools. bembel owns only the objects (routing.html#address-groups).

Access

A subject is a user, a group or a service. A role is a set of permissions. A binding gives a subject a role in a scope. The scope is global, a VRF, a prefix subtree, a zone subtree, a site subtree, a team or a tag. A binding can AND several scope terms. A token is a personal access token that narrows the permissions of its owner. A change request holds a dangerous change until a second subject approves it. An audit event records each change and each denied request. The chapter Access control gives the details.

History and events

Each table has a history table with the old row and a validity range (tstzrange). Thus bembel can show each object at any time, and "who could do what at time T" for bindings. Each change writes, in the same transaction:

  1. the new row and the history row;
  2. an audit event with the subject, the origin (ui, cli, api, assistant, agent, sync or system), the binding that allowed it and the request id;
  3. an outbox row. A worker sends it as a CloudEvents event to the webhooks and to the event stream (api.html#events). It also starts the work that follows: new derived records, a new export bundle, a new embedding.

Derived records are computed in the same transaction as the address. Exports and embeddings are computed after the commit, because they take longer and can be retried.

Each object has one writer. The source tells where the object comes from. The managed_by field tells which integration owns it now.

Schema excerpt

The full schema comes with the code. This excerpt shows how PostgreSQL 18 enforces the main rules. It needs the extensions btree_gist, ltree and vector (pgvector).

CREATE TABLE vrf (
  id          uuid PRIMARY KEY DEFAULT uuidv7(),
  name        text NOT NULL UNIQUE,
  rd          text UNIQUE,
  owner       uuid REFERENCES team,
  revision    bigint NOT NULL DEFAULT 1
);

CREATE TABLE prefix (
  id              uuid PRIMARY KEY DEFAULT uuidv7(),
  vrf_id          uuid NOT NULL REFERENCES vrf,
  cidr            cidr NOT NULL,                     -- the cidr type rejects host bits at input (22P02)
  family          smallint GENERATED ALWAYS AS (family(cidr)) STORED,
  prefix_kind     prefix_kind NOT NULL,              -- container | subnet
  status          prefix_status NOT NULL DEFAULT 'active',  -- planned | active | reserved | deprecated
  is_pool         boolean NOT NULL DEFAULT false,
  parent_id       uuid REFERENCES prefix,            -- kept by trigger
  level           smallint NOT NULL,                 -- containing prefixes in the VRF, kept by trigger
  gateway         inet,
  vlan_id         uuid REFERENCES vlan,
  ib_partition_id uuid REFERENCES ib_partition,
  fabric_id       uuid REFERENCES fabric,
  twin_id         uuid UNIQUE REFERENCES prefix,     -- symmetric; checked by a deferred constraint trigger
  dns_zone_id     uuid REFERENCES zone,
  site_path       ltree,                             -- prefix site
  owner           uuid REFERENCES team,
  tags            jsonb NOT NULL DEFAULT '{}',
  source          text NOT NULL DEFAULT 'local',
  external_ref    text,
  managed_by      text,
  revision        bigint NOT NULL DEFAULT 1,
  CONSTRAINT prefix_unique_per_vrf    UNIQUE (vrf_id, cidr),
  CONSTRAINT prefix_pool_is_container CHECK (NOT is_pool OR prefix_kind = 'container'),
  CONSTRAINT prefix_gateway_inside    CHECK (gateway IS NULL OR gateway << cidr),
  CONSTRAINT prefix_gateway_is_host   CHECK (gateway IS NULL OR masklen(gateway) = CASE family(gateway) WHEN 4 THEN 32 ELSE 128 END),
  CONSTRAINT prefix_vlan_or_partition CHECK (NOT (vlan_id IS NOT NULL AND ib_partition_id IS NOT NULL)),
  -- no two prefixes on the same level of the tree overlap in one VRF
  CONSTRAINT prefix_no_sibling_overlap
    EXCLUDE USING gist (vrf_id WITH =, level WITH =, cidr inet_ops WITH &&)
    DEFERRABLE INITIALLY IMMEDIATE
);
CREATE INDEX prefix_cidr_gist ON prefix USING gist (vrf_id, cidr inet_ops);
CREATE INDEX prefix_site_path ON prefix USING gist (site_path);
CREATE INDEX prefix_owner ON prefix (owner);
CREATE UNIQUE INDEX prefix_source_ref ON prefix (source, external_ref) WHERE external_ref IS NOT NULL;

CREATE TABLE address (
  id               uuid PRIMARY KEY DEFAULT uuidv7(),
  vrf_id           uuid NOT NULL REFERENCES vrf,
  prefix_id        uuid NOT NULL REFERENCES prefix,   -- the subnet
  address          inet NOT NULL,
  status           address_status NOT NULL,           -- allocated | reserved | claimed | deprecated
  shared           boolean NOT NULL DEFAULT false,
  fqdn             text,                              -- drives derived records
  expires_at       timestamptz,                       -- claimed only
  publish          boolean NOT NULL DEFAULT false,    -- export while claimed
  deprecated_until timestamptz,                       -- deprecated only
  observed         boolean NOT NULL DEFAULT false,
  last_seen_at     timestamptz,
  last_seen_source text,                              -- agent, sync or lease source
  owner            uuid REFERENCES team,
  tags             jsonb NOT NULL DEFAULT '{}',
  source           text NOT NULL DEFAULT 'local',
  external_ref     text,
  managed_by       text,
  created_at       timestamptz NOT NULL DEFAULT now(),
  revision         bigint NOT NULL DEFAULT 1,
  CONSTRAINT address_is_host CHECK (masklen(address) = CASE family(address) WHEN 4 THEN 32 ELSE 128 END),
  CONSTRAINT address_claim_has_expiry CHECK ((status = 'claimed') = (expires_at IS NOT NULL)),
  CONSTRAINT address_deprecated_has_grace CHECK ((status = 'deprecated') = (deprecated_until IS NOT NULL)),
  CONSTRAINT address_unique_per_vrf UNIQUE (vrf_id, address)
);
CREATE INDEX address_by_prefix ON address (prefix_id, address);
CREATE INDEX address_claim_expiry ON address (expires_at) WHERE status = 'claimed';
CREATE UNIQUE INDEX address_source_ref ON address (source, external_ref) WHERE external_ref IS NOT NULL;

CREATE TABLE address_interface (                 -- one row, or several for a shared address (trigger)
  address_id   uuid REFERENCES address ON DELETE CASCADE,
  interface_id uuid REFERENCES interface ON DELETE CASCADE,
  PRIMARY KEY (address_id, interface_id)
);

CREATE TABLE object_ref (                        -- more source refs of a merged object
  kind         text NOT NULL,
  object_id    uuid NOT NULL,
  source       text NOT NULL,
  external_ref text NOT NULL,
  UNIQUE (source, external_ref)
);

The trigger on prefix runs before each INSERT, and before each UPDATE of cidr, vrf_id or prefix_kind. It looks for the smallest prefix in the same VRF that contains the new CIDR (cidr >> new.cidr, ordered by masklen descending). It raises SQLSTATE 23514 in two cases:

  • prefix_not_in_subnet: the smallest containing prefix is a subnet. The API answers 409 prefix.inside-subnet.
  • prefix_subnet_childless: the new prefix is a subnet, and the VRF has prefixes inside it. The API answers 409 prefix.subnet-has-children.

Otherwise the trigger sets parent_id to that container, moves the children of the parent that the new prefix contains, and updates level of all descendants. The exclusion uses level and not parent_id, because NULL never equals NULL in an exclusion constraint, so top-level prefixes would not be checked. Two CIDR blocks are either nested or disjoint, so the exclusion fires only when a level is wrong: two concurrent transactions that insert nested prefixes can compute the same level. The exclusion rejects the second with 23P01, and bembel repeats the transaction up to 3 times. The retry computes the right level. If all 3 tries fail, the API answers 409 prefix.overlap (allocation.html#level). A cidr value with host bits gives 22P02 at input, and the API answers 422 validation.failed.

A check trigger on address verifies that address << prefix.cidr and that the prefix is a subnet. A second trigger refuses a second address_interface row for an address with shared = false. The deferred constraint trigger on twin_id checks the twin rules at commit (prefix). A lookup by source ref checks external_ref on the object and the rows of object_ref: the ONA import merges some source rows into one object and keeps their other refs there. The chapter allocation.html#constraints repeats the allocation-relevant parts of this excerpt.
